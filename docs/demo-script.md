# LBS-Master · 3–5 分钟演示口播稿

> 目标：不看代码，按界面点一遍即可讲完。  
> 主路径 Must：OV → 出行双层 → 情景 A/B → 路网/临港 → 导出。  
> 副路径 Should（有时间再点）：能源缺口 → 发起选址 → 治理分色一句。  
> **红线口述：** 不说「我们做了线上 A/B 实验」；不说「这是商用导航/真路况」；业务数标明 **Synthetic**；展示品牌 **小李***。

**准备：** `npm run copy:public-data`（若缺 `public/data`）→ `npm run serve` → http://localhost:4173  
可选：`public/config.local.js` 填高德 Key；无 Key 也能讲（横幅 + fallback 底图）。

## 0:00–0:20 · 时代一句

> 从 PC 搜地点，到移动互联网 LBS 爆发，再到 AI 里 Agent 要「对象在哪、缺口在哪、该补哪」。  
> **入口变了，空间问题没消失。**  
> LBS-Master 不是 C 端导航，也不是单行业 BI，而是 **AI 时代仍需要的「空间对象 + 区域策略 + 多场景编排」中台样板**——上海真空间，经营数据合成，可打开、可带走、可讲解。

## 1:00–2:30 · 主路径 OV → 出行双层（约 1:30）

| 动作 | 口述 |
|------|------|
| 默认 **区域总览** | 分析师第一落点：同一上海域上看结构性缺口，不是一上来盯单点。 |
| 看格、点一格 | 格是统一空间对象；右侧 TopN 是可干预名单的雏形。 |
| 点 **进入出行** / 顶栏「出行」 | 区域、时段、选中格继承——中台全局上下文，不是新开一张孤图。 |
| 确认 demand / supply / gap 同开 | **只看订单热力会误判。** 必须需求 × 运力同屏：该调度还是该刺激，取决于 gap，不是 demand alone。 |
| 指公式 | `gap = demand − supply`（系数来自天气/节点表）；无 supply 不会把 demand 冒充 gap。 |
| 指 TopN + action | 例如 `shift_fleet`：先名单化，再谈策略，而不是拍脑袋赌热区。 |

**可点样例格（可选）：** 陆家嘴一带 `sh:1000:69:61`（与合成校验一致，口述 rain 时 gap 变差）。

## 2:30–3:10 · 情景 A / B（雨天）· 约 0:40

| 动作 | 口述 |
|------|------|
| 情景保持 **A · clear** | 这是 **策略情景对照**（系数表切换），**不是** 线上流量 A/B 实验，也不是天气预报产品。 |
| 切到 **B · rain** | 雨天：叫车需求抬升、有效运力承压 → 同屏 gap 变差；列表与填色重算。 |
| 收一句 | 中台要的是 **可解释的情景杠杆**，让运营回答「雨战加派还是压需求」，而不是另一张静态热力图。 |

## 3:10–3:40 · 路网 / 临港 · 约 0:30

| 动作 | 口述 |
|------|------|
| 勾选 **路网** | OSM 路网经 GCJ 与高德底图配准叠合；用来 **解释可达与走廊**，不是商用导航或真路况引擎。 |
| 点临港 / 过江相关格（或读侧栏文案） | **临港：** 与中心城跨度大，账面有车也可能「够不着」——距离 + 回程空驶放大缺口。 **过江：** 潮汐与通道约束让有效运力低于账面车辆。 |
| 边界一句 | 无 Key 时 fallback 底图可能与 GCJ 路网有视觉偏差；配高德 Key 后按对齐说明讲。 |
