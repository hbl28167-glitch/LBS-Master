# 陆家嘴功能区 V3 试点设计

> 日期：2026-08-29  
> 状态：已完成对话设计，待用户审阅  
> 范围：独立实验，不替换正式 `zones_shanghai`  
> 项目：LBS Master 空间业务问题闭环沙盘

## 1. 背景与问题

现有功能区 V2 以公开地名中心为锚点，采集周边道路节点后生成凸包并轻度外扩。数据统计虽显示多数区面使用 `road_convex_hull`，但凸包会抹平凹口、街巷和真实阻隔，导致区面在地图上仍呈圆形、椭圆形或鼓起的气泡形态。该形态既不像真实城市街区，也削弱了后续覆盖诊断、缺口解释和站网决策的可信度。

本试点验证能否使用真实建筑轮廓与道路围合街区生成自然折线边界，为后续功能分类和全上海重建提供证据。试点只验证几何边界，不同时解决功能分类。

## 2. 目标与非目标

### 2.1 目标

1. 在陆家嘴约 5×5 公里范围内下载并检查开放建筑轮廓。
2. 使用原始 OSM 道路构建拓扑线网，并 polygonize 为自然街区。
3. 将建筑挂接到街区，计算建筑数量、建筑覆盖率和街区面积。
4. 生成 V2 凸包与 V3 街区的并排可视化和量化 QC 报告。
5. 判断该方法是否值得推广到全上海，并明确推广前需要解决的问题。

### 2.2 非目标

- 不在本试点中判断住宅、办公、商业、工业或枢纽类型。
- 不替换 `data/processed/zones_shanghai.geojson`。
- 不改变现有 118 个 `zone_id`、业务指标、契约或正式页面。
- 不建设建筑物级三维模型，不引入建筑高度作为必须字段。
- 不声称试验区块是官方规划红线、宗地或法定功能区。
- 不从地图网站爬取建筑或绕过平台限制。

## 3. 研究范围

试点采用 WGS84 bbox：

```text
west=121.475
south=31.215
east=121.535
north=31.260
```

该范围约 5.7×5.0 公里，覆盖陆家嘴及黄浦江两岸部分高密城区，用于同时检验高密建筑、跨江阻隔、主次道路与城市街区形态。所有 QC 指标均应区分 bbox 内部与距边界 50 米的边缘带，避免把裁切造成的不闭合误判为数据缺陷。

## 4. 数据源与许可

### 4.1 建筑主源

使用 Overture Maps `buildings/building`，按 bbox 提取。Overture 建筑主题融合 OpenStreetMap、Microsoft、Google Open Buildings及东亚建筑数据，并以 OSM 人工维护几何为较高优先级。建筑主题包含 OSM 数据，因此整体按 ODbL 发布。

- 官方说明：https://docs.overturemaps.org/guides/buildings/
- 下载说明：https://docs.overturemaps.org/getting-data/

必须保留每栋建筑的 Overture ID、来源数组和原始 WGS84 几何；报告必须注明 ML 来源可能存在误检、漏检或轮廓精度差异。

### 4.2 道路源

使用原始 OSM/WGS84 道路。优先从项目现有 raw OSM 数据中提取；若现有 raw 无法覆盖 bbox 或缺少必要道路等级，再使用 Geofabrik Shanghai PBF/GPKG 补充。

- 上海提取页：https://download.geofabrik.de/asia/china/shanghai.html

不得直接使用已经转换为 GCJ-02 的 `roads_gcj.geojson` 与 WGS84 建筑进行拓扑计算。

### 4.3 对比源

将当前 `zones_shanghai.geojson` 裁切至试点范围，仅用于 V2/V3 视觉对照，不参与 V3 几何生成。

## 5. 坐标策略

1. Overture 建筑和原始 OSM 道路均以 WGS84 读取。
2. 几何清理、距离、缓冲、面积和 polygonize 统一在 EPSG:32651（WGS 84 / UTM zone 51N）中执行。
3. 输出一份 WGS84 GeoJSON，作为可复现分析产物。
4. 另生成 GCJ-02 展示副本，用于与 LBS Master 前端底图对齐。
5. 任何步骤不得把 WGS84 和 GCJ-02 混合后计算距离或拓扑。

## 6. 处理架构

实验目录：

```text
experiments/zone-v3-lujiazui/
├─ README.md
├─ data/
│  ├─ raw/
│  ├─ interim/
│  └─ processed/
├─ scripts/
├─ report/
└─ preview/
```

处理组件按单一职责拆分：

1. `download-buildings`：按 bbox 下载 Overture 建筑并保存来源元数据。
2. `extract-roads`：从原始 OSM 中提取同范围道路。
3. `clean-linework`：投影、去重、修复无效几何、节点化和有限距离吸附。
4. `polygonize-blocks`：道路线网与 bbox 边界共同生成候选街区。
5. `attach-buildings`：按建筑质心归属街区并计算聚合指标。
6. `qc-blocks`：检查覆盖、重叠、碎片、跨江和异常大区块。
7. `build-preview`：生成 V2/V3 并排预览，不接入正式应用。

各组件通过文件契约连接，任何单步失败不得覆盖上一步产物。

## 7. 道路围合方法

### 7.1 初始切分道路

首轮使用以下 OSM `highway` 等级：

```text
motorway, trunk, primary, secondary, tertiary
及对应 *_link
```

若候选街区面积超过 2,000,000 平方米，再按局部范围加入 `unclassified` 和 `residential` 进行二次细分，避免全量支路直接造成碎片爆炸。

### 7.2 拓扑清理

- 相距不超过 8 米的道路端点允许吸附。
- 仅当两端方向连续且不跨越水体时，允许桥接不超过 20 米的短缺口。
- bbox 边界用于封闭外围区块，但边缘区块必须标记 `edge_clipped=true`。
- 不满足桥接条件的缺口保留为 unresolved，不使用圆形、椭圆或凸包伪造区面。

### 7.3 候选区块清理

- 面积小于 1,000 平方米的候选面标记为 sliver，优先合并至共享边界最长的邻区；无法可靠合并时删除并记录。
- 面积大于 2,000,000 平方米的区块标记为 `oversized`，触发二次道路细分。
- 横跨黄浦江的区块判定为失败，不得进入通过产物。
- 修复后仍无效的几何进入 rejected 文件，不静默丢弃。

## 8. 建筑挂接与统计

建筑使用质心落区作为主要挂接规则；质心未落区但建筑与区块相交比例超过 50% 时，使用最大相交区块。每个街区至少输出：

```text
block_id
geometry_method=road_polygonized_v3
edge_clipped
building_count
building_footprint_m2
block_area_m2
building_coverage_ratio
source_buildings
source_roads
qc_flags
```

本试点不输出正式 `zone_type`，只允许 `classification_status=not_started`。

## 9. 验收与 QC

### 9.1 必须通过

- bbox 内部建筑质心归属率不低于 90%。
- 候选街区相互重叠面积不超过街区总面积的 0.5%。
- 通过产物中不存在无效 Polygon/MultiPolygon。
- 通过产物中不存在横跨黄浦江的单一区块。
- sliver 面积占候选街区总面积不超过 2%。
- 所有区块具有来源、生成方法和 QC 标记。
- GCJ-02 展示副本与项目底图目视对齐，不出现系统性偏移。

### 9.2 作品级目视验收

- 区面边界主要沿可识别道路，不呈规则圆形或椭圆形。
- 陆家嘴高密街区、黄浦江阻隔和主要道路结构肉眼可辨。
- 与 V2 并排时，V3 能明显解释真实城市肌理差异。
- 预览默认不渲染单栋建筑标签，避免信息过载。

### 9.3 规模与性能观察项

- 记录原始建筑数、候选街区数、通过/拒绝数和各阶段耗时。
- GCJ-02 预览区块 GeoJSON 目标不超过 5 MB；超过时先做属性裁剪，不优先简化边界。
- 本地预览首次加载目标不超过 2 秒；若超出，记录瓶颈，不在试点阶段引入切片服务。

## 10. 错误处理与降级

| 情况 | 处理 |
|---|---|
| Overture bbox 下载失败 | 保留日志，不创建空成功文件；可改用官方 DuckDB/GeoParquet方式重试 |
| 建筑覆盖明显不足 | 标记源数据不适用；对比 OSM 建筑，不用合成建筑补洞 |
| 道路无法闭合 | 有限吸附与短缺口桥接；仍失败则标记 unresolved |
| 碎片过多 | 提高切分道路等级，不用凸包回退 |
| 超大区块过多 | 局部加入较低等级道路二次细分 |
| WGS84/GCJ-02 不对齐 | 阻止预览验收，检查转换链；不得手工平移 |
| 跨江区块 | 判为失败并检查水体/道路拓扑，不接受为正常结果 |

## 11. 对比预览

预览必须提供相同镜头下的两栏或切换视图：

- V2：当前 `road_convex_hull` 功能区；
- V3：道路 polygonize 街区；
- 可选建筑轮廓开关，用于解释 V3 街区内部形态；
- QC 面板显示建筑归属率、区块数量、碎片率、异常区块和数据许可。

该预览是实验验收工具，不直接复制成正式产品页面。

## 12. 推广决策

试点完成后只允许三种结论：

1. `go`：QC 和目视均通过，进入功能分类设计与全市扩展计划。
2. `conditional_go`：边界明显改善，但建筑覆盖、道路闭合或性能仍需专项修复。
3. `no_go`：数据覆盖或拓扑质量不足，停止推广并保留实验报告。

只有 `go` 或明确关闭前置问题后的 `conditional_go`，才能讨论替换正式功能区、迁移 `zone_id` 和重建下游指标。

## 13. 事实与对外口径

- 建筑与道路来自开放数据，功能区是算法生成的分析街区，不是官方规划边界。
- 本试点不证明功能类型准确率，也不声称完成全上海重建。
- 数据和几何处理结果必须保留 OSM/Overture 署名与 ODbL要求。
- 试点成功时可描述为“基于开放建筑轮廓与 OSM 道路围合生成自然街区，并通过拓扑和覆盖 QC 验证”；不得描述为真实城市法定功能区。
